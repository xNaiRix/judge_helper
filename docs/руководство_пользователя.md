# Руководство пользователя «Помощник судьи» (упрощённая версия)

Это руководство описывает полный цикл работы с приложением: от регистрации судьи до подведения итогов соревнования. Все примеры используют запущенный сервер `http://127.0.0.1:8000` (о запуске — в [README приложения](../app/README.md)).

## 0. Веб-интерфейс

Приложение имеет **веб-интерфейс** — он открывается в браузере по адресу **http://127.0.0.1:8000/** сразу после запуска сервера (без какой-либо сборки). Все описанные ниже действия можно выполнять через него:

* **Вход / Регистрация** — вкладки на первом экране; при регистрации обязательно согласие 18+; есть восстановление пароля («Забыли пароль?»);
* **Мои соревнования** — таблица с названием, датами, местом, статусом и ролью; здесь же создание нового соревнования;
* **Приглашения** — если вас пригласили в соревнование, над списком появляется карточка «Приглашения в соревнования» с названием, датами, местом, данными администратора, id соревнования и сроком действия — и кнопками «Принять»/«Отклонить»;
* **Карточка соревнования** — кнопки действий для администратора (начать, завершить, удалить, пригласить судью по email), список судей, участники (добавление/удаление до старта);
* **Выставление оценок** — появляется после начала соревнования: для каждого участника поля «Артистизм» и «Техника» (0–10) и комментарий;
* **Результаты** — появляется после завершения: таблица со средними баллами, сортировкой и фильтром по категории; администратор может раскрыть оценки каждого судьи;
* **Выгрузки** — кнопки «Гистограмма (CSV)», «Гистограмма (PNG)» и «Протокол (PDF)» на карточке завершённого соревнования;
* **Статистика по судьям** — администратору: средние оценки каждого судьи и развёрнутый список его баллов;
* **Уведомления** — колокольчик в шапке (с числом непрочитанных) и экран списка;
* **Настройки** — включение/выключение push-уведомлений и их email-дубликатов.

Ниже те же операции описаны через запросы к API (curl). Авторизация — заголовок `Authorization: Bearer <access-токен>`. Интерактивная документация Swagger UI доступна по адресу **http://127.0.0.1:8000/docs**.

## 1. Регистрация судьи

Судья регистрируется один раз: указывает email, ФИО, пароль и **обязательно подтверждает совершеннолетие (18+)**. Без чекбокса 18+ регистрация невозможна.

```bash
curl -X POST http://127.0.0.1:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{
    "email": "ivanov@example.com",
    "full_name": "Иванов Иван Иванович",
    "password": "МойПароль123",
    "adult": true
  }'
```

Ответ (201):

```json
{
  "user": {"id": 1, "email": "ivanov@example.com", "full_name": "Иванов Иван Иванович", "email_confirmed": false},
  "confirmation_token": "J9f8... (в демо-режиме; обычно токен приходит письмом)",
  "message": "Зарегистрировано. Подтвердите email, чтобы войти."
}
```

### Подтверждение email

На email приходит письмо с токеном подтверждения (действует 24 часа). **Без подтверждения войти нельзя** (403). В демо-режиме токен доступен в ответе регистрации:

```bash
curl -X POST http://127.0.0.1:8000/auth/confirm-email \
  -H "Content-Type: application/json" \
  -d '{"token": "<токен из письма>"}'
```

## 2. Вход

```bash
curl -X POST http://127.0.0.1:8000/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "ivanov@example.com", "password": "МойПароль123"}'
```

Ответ (200):

```json
{
  "access_token": "eyJhbGciOi...",
  "refresh_token": "eyJhbGciOi...",
  "user": {"id": 1, "email": "ivanov@example.com", "full_name": "Иванов Иван Иванович", "email_confirmed": true}
}
```

* **Сохраните `access_token`** — он передаётся в заголовке `Authorization: Bearer <access-токен>` во всех дальнейших запросах.
* Когда access истечёт, обновите пару токенов: `POST /auth/refresh` c `{"refresh_token": "..."}`.
* Выход: `POST /auth/logout` (с заголовком авторизации и refresh-токеном в теле) — токены отзываются.
* Неверный email или пароль → `401`; более 5 неудачных попыток за 15 минут → `429`.

### Восстановление пароля

1. `POST /auth/forgot-password` c `{"email": "..."}` — на почту приходит ссылка/токен сброса (24 часа).
2. `POST /auth/reset-password` c `{"token": "...", "new_password": "..."}` — пароль меняется, **все активные сессии завершаются** (нужно войти заново на всех устройствах).

## 3. Создание соревнования (для администратора)

Создатель соревнования автоматически становится его **администратором** и судьёй. Обязательно указать название, место и даты (можно диапазон или перечисление в формате ДД.ММ.ГГГГ).

```bash
curl -X POST http://127.0.0.1:8000/competitions \
  -H "Authorization: Bearer <ваш токен>" -H "Content-Type: application/json" \
  -d '{"name": "Кубок города 2026", "place": "ДК Железнодорожников", "dates": "20.12.2026–21.12.2026"}'
```

Ответ (201): `{"id": 1, "name": "...", "status": "planned", "is_admin": true, ...}` — статус `planned` означает «не начато».

## 4. Список моих соревнований

```bash
curl http://127.0.0.1:8000/competitions -H "Authorization: Bearer <токен>"
```

Показываются только соревнования, где вы судья (включая те, где вы администратор). Для каждого видны название, даты, место и статус: `planned` (не начато), `started` (начато), `finished` (завершено). Удалённые соревнования не отображаются.

## 5. Приглашение судей (только администратор, только до старта)

1. Администратор отправляет приглашение на email судьи:

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/invites \
  -H "Authorization: Bearer <токен администратора>" -H "Content-Type: application/json" \
  -d '{"email": "petrov@example.com"}'
```

2. Судья принимает приглашение (в веб-интерфейсе — карточка «Приглашения в соревнования», либо через API). Список своих приглашений (с данными соревнования и администратора):

```bash
curl http://127.0.0.1:8000/invitations -H "Authorization: Bearer <токен Петрова>"
```

3. Принятие (важно: под своим аккаунтом с этим же email):

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/invites/1/accept \
  -H "Authorization: Bearer <токен Петрова>"
```

Правила:

* **нельзя пригласить судью, который уже состоит в соревновании** (`409`);
* **нельзя отправить повторное приглашение, пока предыдущее не обработано** (`409`) — в один момент времени у судьи либо есть приглашение в данное соревнование, либо нет; после отклонения (или удаления судьи из соревнования) можно отправить снова;
* срок действия приглашения — **1 неделя**; по истечении принять нельзя (`410`);
* после начала соревнования все необработанные приглашения истекают, отклонить их тоже нельзя (`410`);
* отправка новых приглашений после старта запрещена (`403`);
* отклонение: `POST /competitions/1/invites/1/decline`;
* список приглашений (для администратора): `GET /competitions/1/invites`.

## 6. Управление судьями

* Посмотреть всех судей соревнования (ФИО и email) может любой его судья:

```bash
curl http://127.0.0.1:8000/competitions/1/judges -H "Authorization: Bearer <токен>"
```

* Администратор может **до начала** соревнования удалить судью:

```bash
curl -X DELETE http://127.0.0.1:8000/competitions/1/judges/2 -H "Authorization: Bearer <токен администратора>"
```

Удалить самого себя (администратора) нельзя — `403`.

## 7. Добавление участников (только администратор, только до старта)

Карточка участника: фамилия, имя, отчество (необязательно), категория и комментарий.

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/participants \
  -H "Authorization: Bearer <токен администратора>" -H "Content-Type: application/json" \
  -d '{"last_name": "Кузнецов", "first_name": "Алексей", "patronymic": "Сергеевич",
       "category": "Взрослые", "comment": ""}'
```

Правила:

* категории — фиксированный перечень: **Дети, Юниоры, Взрослые, Ветераны**; один участник — одна категория;
* **нельзя добавить двух участников с одинаковым ФИО**. Дубль определяется с нормализацией: регистр, лишние пробелы и «ё»/«е» не различаются; при попытке добавления вернётся `409` с указанием существующей карточки;
* редактирование и удаление карточек — только администратором и только **до начала** соревнования;
* в одном соревновании — до 1000 участников.

Просмотреть список участников может любой судья соревнования: `GET /competitions/1/participants`.

---

## 8. Начало соревнования (администратор)

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/start -H "Authorization: Bearer <токен администратора>"
```

После начала: приглашения рассылать нельзя, состав судей и карточки участников менять нельзя, а **судьи могут выставлять оценки**.

## 9. Выставление оценок (судьи, после начала и до завершения)

Каждый судья оценивает каждого участника по двум критериям: **артистизм** и **техника** — целые числа от 0 до 10. Итоговый балл судьи = сумма оценок (0…20). Можно оставить один комментарий на оценку.

```bash
curl -X PUT http://127.0.0.1:8000/competitions/1/scores/participants/1 \
  -H "Authorization: Bearer <токен судьи>" -H "Content-Type: application/json" \
  -d '{"artistry": 7, "technique": 8, "comment": "Хорошая композиция"}'
```

Правила:

* дробные, отрицательные, больше 10 и нечисловые значения отклоняются (`422`);
* повторная отправка оценки тому же участнику **обновляет** её, а не создаёт дубль;
* до завершения соревнования судья не видит оценки других судей;
* свои оценки с сортировкой и фильтром:

```bash
curl "http://127.0.0.1:8000/competitions/1/scores/my?sort_by=total&order=desc&category=Юниоры" \
  -H "Authorization: Bearer <токен судьи>"
```

## 10. Завершение соревнования (администратор)

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/finish -H "Authorization: Bearer <токен администратора>"
```

Правила:

* завершение **блокируется**, если есть участники без единой оценки — в ответе `409` со списком таких участников;
* если какие-то судьи оценили не всех участников, администратору выдаются **предупреждения** (они не блокируют завершение);
* после завершения выставлять оценки нельзя.

## 11. Результаты (любой судья, после завершения)

```bash
curl "http://127.0.0.1:8000/competitions/1/results?sort_by=competition_score&order=desc" \
  -H "Authorization: Bearer <токен>"
```

Для каждого участника:

* **соревновательный балл** — среднее итоговых баллов всех судей, которые его оценили;
* **итоговая артистичность** и **итоговая техника** — средние по компонентам;
* все средние округляются до 2 знаков после запятой (правило banker's rounding);
* судья, не оценивший участника, в средние по этому участнику не входит;
* сортировка: `sort_by=competition_score|artistry_score|technique_score`, `order=asc|desc`; фильтр: `category=Дети|Юниоры|Взрослые|Ветераны`.

**Администратор** дополнительно видит в каждой карточке разбивку: какой судья сколько поставил за артистизм и технику, итог и комментарий. Обычные судьи оценок других судей не видят.

## 12. Удаление соревнования (администратор)

```bash
curl -X DELETE http://127.0.0.1:8000/competitions/1 -H "Authorization: Bearer <токен администратора>"
```

* до начала — можно;
* во время (начато и не завершено) — **нельзя** (`403`);
* после завершения — можно.
* Удалённое соревнование исчезает из списков; все необработанные приглашения аннулируются.

## 13. Уведомления и настройки

В настройках (⚙ в шапке веб-интерфейса или `GET/PATCH /settings`) включаются:

* **push-уведомления** — приходят о: приглашении в соревнование, удалении из соревнования, начале и завершении соревнования, удалении соревнования; администратору — о принятии/отклонении приглашений; при обновлении оценки с другого устройства;
* **email-дубликаты** — те же уведомления дублируются письмом на ваш адрес.

```bash
curl -X PATCH http://127.0.0.1:8000/settings \
  -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
  -d '{"notifications_enabled": true, "email_notifications_enabled": true}'

curl http://127.0.0.1:8000/notifications -H "Authorization: Bearer <токен>"
```

## 14. Выгрузки после завершения (для судей)

На карточке завершённого соревнования в веб-интерфейсе есть кнопки, те же файлы доступны по API:

* **CSV** — данные гистограммы: для каждой категории и показателя среднее, максимум, минимум и медиана; числа записываются с десятичной запятой и разделителем «;» — файл корректно открывается в Excel с русской локалью (баллы не превращаются в даты);
* **PNG** — гистограмма: 3 столбца на категорию (средние артистичности, техники, соревновательного балла) с зелёной/красной/жёлтой линиями макс/мин/медианы; можно построить как одну категорию (`?category=Юниоры`), так и все вместе;
* **PDF-протокол** — итоговый протокол: участники по категориям (по невозрастанию балла), победители (при равенстве — все), список судей с местами для подписи, расшифровки и даты. Генерация детерминирована: при неизменных данных файл воспроизводится байт в байт.

```bash
curl -OJ http://127.0.0.1:8000/competitions/1/protocol.pdf -H "Authorization: Bearer <токен>"
curl -OJ "http://127.0.0.1:8000/competitions/1/reports/chart.png?category=Юниоры" \
  -H "Authorization: Bearer <токен>"
```

## 15. Статистика по судьям (для администратора)

```bash
curl http://127.0.0.1:8000/competitions/1/judges/stats -H "Authorization: Bearer <токен>"
```

По каждому судье: средние оценки (артистичность, техника, итог) и развёрнутый список — участник, категория, баллы судьи, итоговые баллы и соревновательный балл.

## 16. Офлайн-режим и синхронизация оценок

Если устройство теряло связь, локально накопленные оценки отправляются пакетом с **временем клиента**:

```bash
curl -X POST http://127.0.0.1:8000/competitions/1/scores/sync \
  -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
  -d '{"items": [{"participant_id": 1, "artistry": 8, "technique": 6,
                  "comment": "офлайн", "client_time": "2026-11-16T12:00:00"}]}'
```

Правила (ТЗ): применяется **last-write-wins по времени клиента**; при равенстве времени побеждает запись, принятая сервером позже. Проигравшая запись сохраняется в аудит-логе с пометкой конфликта, дублей в базе не возникает, а судья получает уведомление «Оценка была обновлена с другого устройства».

## 17. Автоудаление соревнований

Завершённое соревнование **автоматически удаляется через год** после завершения (без уведомлений). Администратор может удалить соревнование вручную и раньше — до начала или после завершения (см. раздел 12).

## Частые ошибки

| Код | Причина |
| :--- | :--- |
| 401 | неверный/просроченный/отозванный токен (`Authorization: Bearer`) |
| 403 | действие не для вашей роли (не администратор), email не подтверждён или не в тот статус соревнования |
| 404 | соревнование/участник не найдены **или** вы не судья этого соревнования; Google OAuth выключен |
| 409 | дубль ФИО, повторное принятие приглашения, завершение с неоценёнными участниками |
| 410 | приглашение истекло (неделя или старт соревнования); истёк токен подтверждения/сброса |
| 422 | некорректные данные (оценка вне 0..10, категория вне перечня, нет 18+ и т.п.) |
| 429 | превышен лимит: 100 запросов/мин с одного IP или 5 неудачных попыток входа за 15 минут |
