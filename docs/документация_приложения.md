# Техническая документация приложения «Помощник судьи»

Версия: 2.0.0
Стек: Python 3.11, FastAPI, SQLAlchemy 2.x, JWT (PyJWT), Pillow (PNG), ReportLab (PDF), SQLite (по умолчанию) / PostgreSQL (через `DATABASE_URL`).
Код: каталог [`app/`](../app), пакет `judge_helper`.

---

## 1. Назначение

Реализация ТЗ «Приложение «Помощник судьи»»: регистрация судей с подтверждением email, соревнования с полным жизненным циклом (включая автоудаление через год), приглашения, участники с защитой от дублей ФИО, оценки с офлайн-синхронизацией (LWW), подведение результатов с banker's rounding, уведомления с настройками, аудит-лог, отчёты (CSV/PNG/PDF), статистика по судьям, rate limiting и RELEASE-логи. Проект служит объектом тестирования дисциплины «Тестирование и верификация программного кода».

## 2. Архитектура

```
┌──────────────────────────────────────────────────────────────────┐
│                        FastAPI приложение                         │
│                                                                   │
│  middleware.py        request_id, RELEASE-логи (без ПД),          │
│                       rate limit 100 req/min/IP, login throttle   │
│  routers/             auth, users, competitions, participants,    │
│                       scores (+sync), results, reports            │
│  schemas.py           Pydantic: валидация входа/выхода            │
│  services.py          права доступа, аудит, уведомления,          │
│                       регламентные операции (sweep_expired)       │
│  security.py          PBKDF2-пароли, JWT access/refresh           │
│  utils.py             нормализация ФИО, banker's rounding         │
│  models.py            ORM-модели                                  │
│  settings.py          конфигурация из env (флаги, лимиты, сроки)  │
│  static/index.html    веб-интерфейс (без сборки)                  │
└──────────────────────────────────────────────────────────────────┘
```

Аутентификация: **JWT (HS256)** — access (8 ч) + refresh (30 д). Проверяются подпись, срок, алгоритм и тип токена. Logout отзывает jti (таблица `revoked_tokens`). Сброс пароля инкрементирует `token_version` → все ранее выданные токены становятся недействительными (все сессии завершаются). Заголовок: `Authorization: Bearer <access>`.

## 3. Модель данных

| Таблица | Назначение | Ключевые ограничения |
| :--- | :--- | :--- |
| `users` | судьи | email уникален; `email_confirmed`, `token_version`, настройки уведомлений |
| `competitions` | соревнования | status ∈ planned/started/finished; soft-delete; `finished_at` для автоудаления |
| `judges` | связь судья–соревнование | UQ (competition_id, user_id) |
| `invites` | приглашения | статус + `expires_at` (1 неделя) |
| `participants` | карточки участников | UQ (competition_id, normalized_fio) |
| `scores` | оценки | UQ (competition_id, judge_id, participant_id); `client_time`, `server_received_at` для LWW |
| `auth_tokens` | одноразовые токены (подтверждение email / сброс пароля, 24 ч) | token уникален, `used` |
| `revoked_tokens` | отозванные JWT (logout) | jti уникален |
| `notifications` | уведомления пользователей | kind, read |
| `email_outbox` | имитация исходящих писем | — |
| `audit_log` | аудит-лог (6 месяцев) | ip, user_agent, request_id, `conflict_overwritten` |

## 4. Бизнес-правила (ТЗ)

1. **Регистрация**: email + ФИО + пароль + обязательный чекбокс 18+; вход запрещён до подтверждения email; восстановление пароля — ссылка 24 ч, завершает все сессии.
2. **Соревнование**: создатель = администратор и судья; статусы planned → started → finished; удаление — до начала или после завершения (soft-delete + аннулирование приглашений + уведомления судьям при ручном удалении); **автоудаление через 365 дней** после завершения (без уведомлений, ленивый sweep).
3. **Приглашения**: только администратором и до старта; срок 1 неделя; после старта истекают, принять/отклонить нельзя (410).
4. **Участники**: CRUD только администратором и до старта; категории Дети/Юниоры/Взрослые/Ветераны; до 1000; дубли ФИО по нормализации (trim, схлопывание пробелов, нижний регистр, «ё»=«е»; дефисы и апострофы значимы).
5. **Оценки**: целые 0..10 × 2 критерия; только судьи соревнования и только в статусе started; upsert по (судья, участник, соревнование).
6. **Офлайн-синхронизация**: `POST /competitions/{id}/scores/sync` — LWW по клиентскому времени; при равенстве — по времени приёма сервером (позже принятая побеждает); проигравшая запись — в аудит с `conflict_overwritten`; уведомление «Оценка была обновлена с другого устройства»; дублей нет.
7. **Завершение**: блокируется при участниках без оценок (409 + список); предупреждения о неоценивших судьях — не блокирующие.
8. **Результаты**: соревновательный балл / итоговая артистичность / итоговая техника — средние по оценившим судьям, округление 2 знака (banker's rounding), пустой набор → null; сортировка asc/desc, фильтр по категории; администратору — разбивка по судьям.
9. **Уведомления**: приглашение, удаление из соревнования, начало, завершение, удаление соревнования (ручное), статус приглашения (администратору); дублирование на email по настройке.
10. **Аудит**: все значимые действия; для оценок — старый/новый балл и комментарий; хранение 6 месяцев.
11. **Протокол PDF**: категории (участники по невозрастанию балла), победители (с учётом равенства), судьи с местами для подписи/расшифровки/даты; генерация детерминирована (`invariant=1`).
12. **Безопасность**: rate limit 100 req/min/IP (429); 5 неудачных входов за 15 минут (429); RELEASE-логи без ПД; X-Request-ID в каждом ответе.

## 6. API-референс

База: `http://127.0.0.1:8000`. Swagger UI — `/docs`. Защищённые методы требуют `Authorization: Bearer <access>`.

### 6.1 Авторизация

| Метод | Путь | Описание | Коды |
| :--- | :--- | :--- | :--- |
| POST | `/auth/register` | регистрация (18+ обязательно); письмо с токеном подтверждения | 201; 409; 422 |
| POST | `/auth/confirm-email` | подтверждение email (24 ч) | 200; 400; 410 |
| POST | `/auth/login` | вход (после подтверждения) | 200; 401; 403 неподтверждён; 429 |
| POST | `/auth/refresh` | обновление access | 200; 401 |
| POST | `/auth/logout` | отзыв токенов | 204 |
| POST | `/auth/forgot-password` | запрос сброса (24 ч) | 200 |
| POST | `/auth/reset-password` | сброс пароля; завершает все сессии | 200; 400; 410 |
| GET | `/auth/google/url` | ссылка OAuth (feature flag) | 200; 404; 501 |
| POST | `/auth/google/callback` | обмен кода (требует настройки клиента) | 404; 501 |
| GET | `/auth/me` | текущий пользователь | 200; 401 |

### 6.2 Пользователь

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| GET/PATCH | `/settings` | настройки уведомлений (push, email) |
| GET | `/notifications?unread_only=` | список уведомлений |
| POST | `/notifications/read-all` | пометить прочитанными |
| GET | `/invitations` | мои активные приглашения: название, даты, место, администратор, id соревнования, срок действия |

### 6.3 Соревнования

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| POST/GET | `/competitions` | создать / список моих (срабатывает автоудаление старых) |
| GET | `/competitions/{id}` | детали + судьи (только участникам) |
| DELETE | `/competitions/{id}` | удалить (до начала / после завершения) |
| POST | `…/start`, `…/finish` | начать / завершить (администратор) |
| GET | `…/judges` | список судей |
| DELETE | `…/judges/{uid}` | удалить судью (до старта, не админа) |
| POST/GET | `…/invites`, `…/invites/{iid}/accept\|decline` | приглашения (1 неделя, до старта; 409 — если судья уже в соревновании или приглашение уже висит неотвеченным) |

### 6.4 Участники

`GET/POST /competitions/{id}/participants`, `PATCH/DELETE …/participants/{pid}` — правила как в ТЗ; 409 при дубле ФИО (с существующей карточкой), 400 при лимите 1000.

### 6.5 Оценки

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| PUT | `…/scores/participants/{pid}` | выставить/обновить (только в статусе started) |
| POST | `…/scores/sync` | офлайн-синхронизация: `{items: [{participant_id, artistry, technique, comment, client_time}]}` → `{applied, skipped, results[]}`; LWW + conflict_overwritten в аудите |
| GET | `…/scores/my?sort_by=&order=&category=` | свои оценки |

### 6.6 Результаты и отчёты (после завершения)

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| GET | `…/results?sort_by=&order=&category=` | итоговая таблица (админу — разбивка по судьям) |
| GET | `…/judges/stats` | список по судьям с развёрнутыми баллами (только администратор) |
| GET | `…/reports/chart.csv` | данные гистограммы: категория × показатель × среднее/макс/мин/медиана |
| GET | `…/reports/chart.png?category=` | PNG-гистограмма (3 столбца на категорию + линии макс/мин/медиана; одна категория или все) |
| GET | `…/protocol.pdf` | детерминированный PDF-протокол |

## 7. Логирование и аудит

* **RELEASE-логи** (уровень INFO): `request_id, endpoint, method, status_code, duration_ms` — без email, ФИО, оценок, токенов и IP; каждый ответ содержит заголовок `X-Request-ID`.
* **DEBUG-логи** включаются `APP_DEBUG=1` (только dev/staging).
* **Аудит-лог** — таблица `audit_log`: действия create/update/delete/start/finish/invite/accept/decline/conflict; поля ts, user_id, role, entity_type, entity_id, old_value, new_value, ip, user_agent, request_id, conflict_overwritten. Очистка старше 180 дней — в `sweep_expired()`.
