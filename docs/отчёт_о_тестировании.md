## 2. Краткое резюме (Executive Summary)

**Вердикт: Go — продукт готов к приёмке (UAT) и передаче заказчику.**

Все функциональные тест-кейсы выполнены и пройдены; подтверждённые дефекты исправлены и закрыты
повторным тестированием. Автотесты (211 тестов, [app/tests/](../app/tests)) интегрированы в CI/CD,
покрытие кода — **97%** при пороге ТЗ 80%. Критерии выхода из [плана](план_тестирования.md), раздел 12,
выполнены: Blocker и Critical дефектов на релиз-кандидате — 0, покрытие кода ≥ 80%,
трассируемость «требование → кейс → результат» полная (TestY).

Топ-3 оставшихся риска: (1) нагрузочные проверки на прод-подобном стенде (2 кейса заблокированы,
перенесены в UAT), (2) отложенный дефект DEF-04 (формат дат в CSV), (3) UAT с реальными судьями —
запланирован на приёмке.

## 3. Объём тестирования (Scope)

**Тестировалось** (по разделам плана):

* функциональные кейсы по модулям (раздел 7: авторизация с подтверждением email, соревнования,
  приглашения, участники, оценки с офлайн-синхронизацией, результаты, отчёты CSV/PNG/PDF,
  уведомления, аудит);
* матрица прав доступа (раздел 8: IDOR, подмена роли, повторное приглашение, доступ не-участника);
* NFR-кейсы (раздел 9: производительность, надёжность, безопасность, совместимость, доступность,
  локализация, ретеншн, поддерживаемость, правовые);
* UAT-сценарии с метриками приёмки (раздел 10).

**Не тестировалось** (границы из плана, раздел 2): передача прав администратора (не предусмотрено ТЗ),
реальные персональные данные (использованы синтетические), маркетинг и поддержка после гарантии.

**Окружения**: Windows 11 (ручное тестирование, Chrome 130 / Firefox 133); приложение FastAPI +
SQLite/Docker; CI: GitHub Actions, Python 3.11 и 3.12; TMS TestY 2.2.1 (Docker Compose).

## 5. Отклонения и препятствия

* Нагрузочное тестирование (2 кейса раздела 9.1) выполнено в ограниченном объёме: нет стенда,
  повторяющего прод; базовые проверки отклика выполнены локально, полная нагрузка перенесена в UAT.
* Развёртывание TestY на Windows потребовало обхода известных проблем (`core.autocrlf=input`,
  кириллические пути) — зафиксировано в [docs/testy_руководство.md](testy_руководство.md), раздел 4.3.
* Один кейс был ошибочно помечен Failed (DEF-05) — отклонён триажем, перетест пройден.

## 6. Оценка качества и оставшиеся риски

| Риск | Влияние | Митигация |

| DEF-04: даты в CSV в UTC | Минимальное: формат CSV — серая зона ТЗ | Задокументировано в известных ограничениях; правка в следующей версии |
| Нагрузка не измерена полностью | Среднее: NFR 9.1 | Перенесено в UAT; базовые замеры выполнены |

| Офлайн-синхронизация (LWW) проверена на уровне API | Низкое: конфликтные сценарии покрыты автотестами | E2E-проверка на реальных устройствах — в UAT |

## 7. Выводы и рекомендации

1. По критериям выхода (план, раздел 12) и результатам цикла — **рекомендация Go**: продукт
   функционально полон, регрессия зелёная, критические дефекты отсутствуют.
2. Обязательное условие приёмки — проведение UAT с ≥ 10 судьями по сценариям раздела 10 плана
   и снятие метрик приёмки из ТЗ.
3. В следующую итерацию: вынести формат дат CSV в ТЗ и закрыть DEF-04; добавить property-based
   генеративные проверки API (Schemathesis) в CI; рассмотреть прод-подобный стенд для полной
   валидации NFR 9.1.
