# Помощник судьи — приложение

Проект по дисциплине **«Тестирование и верификация программного кода»**.
Реализация [ТЗ](../docs/ТЗ.md) «Приложение «Помощник судьи»» на **FastAPI + SQLAlchemy** с веб-интерфейсом.

[![CI](../../actions/workflows/ci.yml/badge.svg)](../../actions/workflows/ci.yml)

## Что реализовано

| Область | Функции |
| :--- | :--- |
| Авторизация | регистрация (email, ФИО, пароль, обязательный чекбокс 18+), **подтверждение email** (вход запрещён до подтверждения), JWT (access + refresh, проверка подписи/срока/алгоритма), logout с отзывом токенов, **восстановление пароля** (ссылка 24 ч, завершает все сессии), **Google OAuth как feature flag** (`GOOGLE_OAUTH_ENABLED`: 404 при выключенном) |
| Соревнования | создание (создатель = администратор + судья), список «моих», статусы, soft-delete по правилам ТЗ (до начала / после завершения), **автоудаление через год** после завершения |
| Приглашения | по email, только администратором и до старта, срок 1 неделя, принятие/отклонение адресатом, истечение после старта |
| Судьи | список, удаление (до старта, кроме администратора) |
| Участники | карточки (ФИО, категория, комментарий), CRUD до старта, защита от дублей ФИО с нормализацией (регистр, пробелы, «ё»=«е», значимые дефисы), лимит 1000 |
| Оценки | целые 0..10 за артистизм/технику + комментарий, upsert с уникальностью (судья, участник, соревнование) |
| **Офлайн-синхронизация** | `POST /scores/sync`: локальная очередь оценок, **LWW по клиентскому времени**, при равенстве — по времени приёма сервером; проигравшая запись — в аудит-лог с `conflict_overwritten`, дублей не возникает, уведомление «Оценка была обновлена с другого устройства» |
| Завершение | блокировка при участниках без оценок (со списком), неблокирующие предупреждения о судьях |
| Результаты | средние с banker's rounding (2 знака), пустой набор → null, сортировки/фильтры, разбивка по судьям для администратора |
| **Статистика по судьям** | средние оценки каждого судьи + развёрнутый список его баллов (только администратор) |
| **Отчёты** | **CSV** и **PNG-гистограмма** (3 столбца на категорию: средние артистичности/техники/балла + линии макс/мин/медиана; одна категория или все вместе), **PDF-протокол** (категории, победители с учётом равенства, судьи с местами для подписи; генерация детерминирована) |
| **Уведомления** | настройки push/email; события: приглашение, удаление из соревнования, начало, завершение, удаление соревнования, статус приглашения (администратору), обновление оценки с другого устройства |
| **Аудит-лог** | timestamp, user_id, role, action, entity, old/new value, ip, user_agent, request_id; хранение 6 месяцев (очистка) |
| Безопасность | PBKDF2-хэши паролей, **rate limit 100 запросов/мин с IP**, **5 неудачных входов за 15 минут**, RELEASE-логи без ПД, X-Request-ID |
| Веб-интерфейс | одна страница без сборки: вход/регистрация (с 18+ и подтверждением email в демо-режиме), восстановление пароля, соревнования, участники, оценки, результаты, уведомления, настройки, выгрузки CSV/PNG/PDF, статистика по судьям |

## Упрощения относительно полного ТЗ

* **SQLite** по умолчанию вместо PostgreSQL (переключается `DATABASE_URL`); Redis и S3 не используются — в приложении нет кэшируемых и файловых данных;
* email-отправка **имитируется** таблицей-аутбоксом (в демо-режиме `ECHO_EMAIL_TOKENS=1` токены возвращаются в ответе API; в production выключить — тогда токен только из письма);
* Google OAuth: реализован feature flag и построение ссылки авторизации; **обмен кода** требует настроенного клиента и секретов на сервере (501);
* push-доставка — внутренняя таблица уведомлений (FCM/APNs не подключаются в учебном окружении);
* NFR (производительность p95, SUS, WCAG) измеряются тест-кейсами TestY, но не в этом коде.

```
app/
├── src/judge_helper/
│   ├── main.py            # фабрика приложения
│   ├── asgi.py            # точка входа uvicorn
│   ├── settings.py        # конфигурация (env): JWT, флаги, лимиты, сроки
│   ├── models.py          # ORM-модели
│   ├── schemas.py         # Pydantic-схемы
│   ├── services.py        # бизнес-правила, аудит, уведомления, регламент
│   ├── security.py        # PBKDF2 + JWT
│   ├── middleware.py      # request_id, RELEASE-логи, rate limit
│   ├── utils.py           # нормализация ФИО, banker's rounding
│   ├── static/index.html  # веб-интерфейс (без сборки)
│   └── routers/           # auth, users, competitions, participants,
│                          # scores (вкл. sync), results, reports (CSV/PNG/PDF)
├── scripts/e2e_demo.py    # сквозной демо-сценарий полного цикла (26 шагов)
└── tests/                 # 186 автотестов
 ```

## Быстрый старт

```bash
cd app
python -m venv .venv
.venv\Scripts\activate            # Windows
# source .venv/bin/activate       # Linux/macOS

pip install -r requirements-dev.txt

# запуск сервера разработки
python -m uvicorn judge_helper.asgi:app --reload --app-dir src
```

### Docker

```bash
cd app
docker compose up --build             # http://127.0.0.1:8000/ (данные — в volume judge_data)

# или вручную
docker build -t judge-helper .
docker run --rm -p 8000:8000 -e APP_SECRET_KEY=secret -v judge_data:/data judge-helper
```

* Образ: multi-stage (venv собирается в builder), пользователь `app` (non-root), шрифты DejaVu для PDF-отчётов;
* переменные: `APP_SECRET_KEY`, `ECHO_EMAIL_TOKENS` (по умолчанию 1 — демо), `RATE_LIMIT_PER_MIN`, `DATABASE_URL` (по умолчанию `sqlite:////data/judge_helper.db`);
* healthcheck: `GET /health`.

* Веб-интерфейс: http://127.0.0.1:8000/
* Swagger UI: http://127.0.0.1:8000/docs

### Переменные окружения

| Переменная | По умолчанию | Описание |
| :--- | :--- | :--- |
| `DATABASE_URL` | `sqlite:///./judge_helper.db` | БД (можно PostgreSQL) |
| `APP_SECRET_KEY` | dev-значение | секрет подписи JWT (сменить в prod!) |
| `GOOGLE_OAUTH_ENABLED` | `0` | feature flag Google OAuth |
| `GOOGLE_CLIENT_ID` | — | клиент Google OAuth |
| `ECHO_EMAIL_TOKENS` | `1` | демо-режим: токены писем в ответе API (выключить в prod) |
| `RATE_LIMIT_PER_MIN` | `100` | лимит запросов с одного IP |
| `ACCESS_TOKEN_TTL_MIN` / `REFRESH_TOKEN_TTL_DAYS` | 480 / 30 | срок жизни токенов |
| `APP_DEBUG` | `0` | DEBUG-логи (только dev/staging) |

## Тесты и покрытие

```bash
pytest                                                # все тесты
pytest --cov=judge_helper --cov-report=term-missing   # с покрытием
```

* **186 автотестов**: unit (`test_utils.py`), API (остальные), веб-интерфейс (`test_web_ui.py`);
* покрытие — **97%** (порог CI — 80% по ТЗ);
* новые группы тестов: подтверждение email/сброс пароля/JWT (`test_auth_api.py`), уведомления (`test_notifications.py`), аудит (`test_audit.py`), офлайн-синхронизация LWW (`test_sync.py`), отчёты CSV/PNG/PDF и автоудаление (`test_reports.py`), лимиты (`test_limits.py`).

## Сквозной демо-сценарий

Против запущенного сервера можно выполнить полный цикл по ТЗ одной командой
(регистрация с подтверждением email → соревнование → приглашения → участники →
старт → оценки и офлайн-синхронизация → завершение → результаты → статистика
судей → CSV/PNG/PDF → уведомления → сброс пароля):

```bash
python scripts/e2e_demo.py http://127.0.0.1:8000
```
